# Round 1: Independent Critical Reviews

## T1: Security & Compliance Review

### Scorecard
| Section | Verdict | Rationale |
|---------|---------|-----------|
| Binary Secret Scan Fix | **Critical Gap** | UTF-16/32 is just the start. What about base64-encoded secrets? Encrypted blobs? Image steganography? The scanner needs a **multi-pass pipeline**: decode → classify → scan, not just "fix UTF-16". |
| JVM/Go/Swift/.NET/C++ Deep License Scan | **Critical Gap** | "Not checked" = false negative. Need **mandatory lockfile parsing** for each ecosystem: `pom.xml`/`build.gradle` → `license-maven-plugin`, `go.mod` → `go-licenses`, `Package.swift` → `swift-license`, `Cargo.toml` → `cargo-deny`, `*.csproj` → `dotnet-licenses`. Must fail closed if tool missing. |
| Supply Chain Quality Dimension | **Major Gap** | SBOM generation alone is insufficient. Need **SLSA provenance** (build attestation), **signature verification** (cosign), **dependency confusion detection**, **typosquatting alerts**. The dimension must be **enforceable in CI**, not just publish-time. |
| Tiny AI Guardrail Gap | **Critical Gap** | AI features on Tiny have **zero independent review**. The `responsible-ai-reviewer` only activates Standard+. This is a **regulatory liability** (EU AI Act, US EO 14110). Every AI feature needs guardrail verification regardless of Tier. |
| Gate TTL (60 min) | **Major Gap** | 60 minutes is **too long** for high-security contexts. Need **configurable TTL** per project (env var: `GRU953_GATE_TTL_MINUTES`), with **default 15 min** for projects handling money/PII. |
| Secrets in Git LFS/Submodules | **Critical Gap** | `scan.mjs` only scans working tree + index + untracked + history. **Misses**: LFS pointers (actual content in LFS store), submodules (separate repos), git worktrees (other branches). Need explicit LFS/submodule scanning. |
| No Runtime Secret Detection | **Major Gap** | Only static scan. No **runtime secret detection** (env var scanning at startup, process memory scanning for injected secrets). |
| Content Rights Verification | **Critical Gap** | `content-check.mjs` only checks *presence* of rights field, not *validity*. "CC0" claimed for Gemini output is **legally false** (Google ToS). Need **provider-specific rights matrix** with automated validation. |

### Blocking Concerns
1. **Regulatory non-compliance** - Tiny AI features ship without fairness review
2. **False negative license scans** - Copyleft deps can ship undetected
3. **Gate TTL too permissive** - Stolen token valid for 60 min
4. **Content rights theater** - Rights field present but semantically meaningless

### Refinement Proposals
- Replace "fix UTF-16" with **multi-pass secret pipeline** (decode → normalize → scan)
- Mandate **lockfile-based license extraction** for ALL ecosystems with fail-closed
- Add **SLSA Level 2+** as supply chain dimension requirement
- Move `responsible-ai-reviewer` to **all Tiers** for AI features
- Make gate TTL **configurable with secure default (15 min)**
- Add **LFS/submodule scanning** to `scan.mjs`
- Implement **provider-specific rights validation matrix**

## T2: Architecture & Platform Review

| Section | Verdict | Rationale |

Needs **concrete defaults**: Next.js 15 (App Router), Astro, Remix, TanStack Start, Hono, Elysia. | Architecture Decision Records | **Major Gap** | No ADR template. `Dev-Memory/decisions/*.md` has **no structure**. Need: **MADR format** (Markdown Architectural Decision Records) with: Status, Context, Decision, Consequences, Links. Enforced by `repo-integrity.mjs`. |
| Interface Contracts | **Critical Gap** | "Define interface contracts precisely" but **no enforcement**. Need: **OpenAPI 3.1** for REST, **Protobuf/gRPC** for services, **GraphQL Schema** for GraphQL, **TypeScript interfaces** for internal. **Contract tests** (Pact) mandatory for service boundaries. |

| Performance Budgets | **Critical Gap** | No non-functional requirements in design. Need: **Bundle size budget**, **TTI/LCP budgets**, **Memory/CPU budgets**, **Cold start budgets** (serverless). Enforced in CI via `webpack-bundle-analyzer`, `lighthouse-ci`, `clinic.js`. |

### Blocking Concerns
1. **7 platforms in Phase 2** - will stall entire roadmap
2. **No contract enforcement** - interfaces drift silently
3. **Vague stack menu** - architects default to familiar, not optimal
4. **No monorepo support** - blocks enterprise adoption

### Refinement Proposals
- **Phase 2**: Tauri v2 (desktop) + React Native/Expo (mobile) ONLY
- **Phase 3**: Serverless/Edge (Vercel, Cloudflare Workers, Deno Deploy)
- **Phase 4**: WASI + Wails (if demand)
- Mandate **MADR format** for all decisions with `repo-integrity` check
- Add **contract testing** (Pact) as quality dimension
- Define **concrete stack defaults** with version pins in `architect.md`
- Add **performance budgets** to `ARCHITECTURE.md` template
- Add **monorepo detection** + workspace-aware Build Swarm

## T4: Testing & Quality Review

### Scorecard
| Section | Verdict | Rationale |
|---------|---------|-----------|
| TDD Only Standard/Complex | **Critical Gap** | Tiny projects **ship untested code**. "Basic checks" = manual verification. Need **minimum test requirement per Tier**: Tiny = 1 integration test + 1 unit test per task; Standard = TDD + property-based; Complex = + mutation + contract. |
| No Property-Based Testing | **Critical Gap** | **Zero mention** of: `fast-check` (TS), `hypothesis` (Python), `proptest` (Rust), `gopter` (Go), `jqwik` (Java), `hypothesis` (Kotlin), `cppcheck`/`rapidcheck` (C++), `swiftcheck` (Swift), `cscheck` (C#), `dart_check` (Dart). This is **table stakes** for quality. |
| No Contract Testing | **Critical Gap** | Service boundaries **untested**. Need **Pact** (consumer-driven contracts) for: REST (OpenAPI), gRPC (Protobuf), GraphQL (Schema), Message queues (AsyncAPI). Enforced at **build time**, not publish. |
| No Mutation Testing | **Major Gap** | Test quality **unverified**. Need: `stryker` (TS), `mutmut` (Python), `cargo-mutants` (Rust), `go-mutesting` (Go), `pitest` (Java/Kotlin), `mutcpp` (C++), `swift-mutator` (Swift), `mutant` (C#), `dart_mutation` (Dart). **Minimum 80% mutation score** for Standard+. |
| Browser Automation Optional | **Critical Gap** | "If Playwright MCP available" = **flaky by design**. Need: **Mandatory visual regression** (Playwright + pixelmatch) for ANY UI project. **Headless Chromium** bundled or **CI dependency**. Fallback: **Storybook + Chromatic** for component-level. |
| Test Evidence Format | **Major Gap** | `verified: <cmd> → exit 0 (date)` is **human-readable, machine-opaque**. Need: **Structured evidence** (JSON): `{taskId, criterion, command, exitCode, stdout, stderr, duration, artifacts[]}`. Parsed by CI dashboards. |
| No Test Parallelization Guidance | **Major Gap** | Build Swarm runs 2 builders but **tests run sequentially**. Need: **Test sharding** by task dependency graph, **parallel test execution** per language (`pytest-xdist`, `vitest --pool`, `cargo nextest`, `go test -p`), **flaky test quarantine**. |
| No Test Data Management | **Major Gap** | **Zero strategy** for: fixtures, factories, snapshots, database seeding, test containers. Each language needs: **Testcontainers** (Java/Go/Python/TS/Rust), **FactoryBot** equivalents, **Snapshot testing** (`insta`, `snapbox`, `jest-snapshot`). |

### Blocking Concerns
1. **Tiny ships untested** - violates "working MVP" promise
2. **No property-based/contract/mutation** - tests only catch known bugs
3. **Visual regression optional** - UI bugs ship silently
4. **Evidence not machine-parseable** - no CI dashboard, no trends

### Refinement Proposals
- **Tiered test requirements**: Tiny (min 2 tests/task), Standard (TDD + property), Complex (+ mutation + contract)
- **Mandate property-based testing** in all `lang-*` skills with baseline configs
- **Add contract testing** (Pact) as quality dimension for service boundaries
- **Add mutation testing** gate (80% score) for Standard/Complex
- **Bundle Playwright** in CI image; make visual regression **mandatory for UI**
- **Structured evidence format** (JSON) replacing `verified:` free text
- **Test sharding** by `PLAN.md` dependency graph
- **Testcontainers/factory/snapshot** patterns in each `lang-*` skill

## T5: AI/ML & Model Operations Review

### Scorecard
| Section | Verdict | Rationale |
|---------|---------|-----------|
| Multi-Provider Routing | **Major Gap** | "Route to cheapest capable provider" - **no capability matrix defined**. Need: **Capability registry** per provider: function calling, vision, reasoning, code gen, JSON mode, structured output, context window, latency, cost/1k tokens. **Router must query registry at runtime**. |
| Latency-Aware Routing | **Major Gap** | No **latency SLOs** per task type. Interactive (<500ms) vs batch (<30s) vs reasoning (<5min). Router needs **latency budgets** and **fallback chains** with measured latency. |
| Cost Tracking Per Provider | **Aligned** | `cost-monitor` logs spend - good. **Missing**: **Per-provider budget alerts**, **cost anomaly detection**, **projected monthly cost** from current velocity. |
| Fallback Chains | **Major Gap** | "Primary → Secondary → Tertiary" but **no health checks**. Need: **Circuit breakers** per provider, **automatic failover** with user notification, **degraded mode** (e.g., disable vision if vision provider down). |
| Model Benchmarking | **Critical Gap** | "Periodic eval" - **no benchmark suite defined**. Need: **Standardized eval harness** per capability: HumanEval+/MBPP (code), GSM8K/MATH (reasoning), MMLU (knowledge), custom project-specific evals. **Automated nightly runs** with regression detection. |
| Agentic Workflows | **Over-scoped** | "LangGraph/AutoGen patterns" - **premature**. Current architecture is **sequential delegation**. Agentic = **cycles, loops, dynamic tool selection**. Need: **Explicit architecture decision** (RFC) before building. Start with **structured output + tool use** (already in Claude). |
| RAG Integration | **Major Gap** | "Knowledge retrieval for codebase-aware" - **no retrieval strategy**. Need: **Code indexing** (Tree-sitter + embeddings), **Retrieval strategy** (hybrid: keyword + semantic), **Context window management** (reranking, compression), **Citation/grounding** verification. |
| Fine-Tuning Pipeline | **Over-scoped** | LoRA/QLoRA for project-specific models - **niche use case**. Most projects need **prompt engineering + RAG**, not fine-tuning. **Defer to explicit user request** with clear cost/benefit analysis. |
| Prompt Optimization | **Major Gap** | DSPy/APE/evolutionary - **research-grade**. Need **practical first**: **Few-shot examples** from `LESSONS.md`, **Prompt templates** with variable injection, **A/B testing framework** for prompt variants, **Versioned prompt registry** (git-tracked). |
| Evaluation Harness | **Critical Gap** | **No evaluation infrastructure**. Need: **Custom metrics** (code compiles, tests pass, style matches), **LLM-as-judge** with calibrated prompts, **Human eval UI** for subjective quality, **Regression detection** (new prompt worse than old). |

### Blocking Concerns
1. **No capability registry** - routing is guesswork
2. **No eval harness** - can't verify model quality
3. **Agentic/RAG/Fine-tuning over-scoped** - distracts from core routing
4. **No circuit breakers** - provider outage = silent failure

### Refinement Proposals
- **Build capability registry first** (YAML/JSON per provider, versioned)
- **Implement eval harness** with 3 tiers: automated (code/test), LLM-judge, human
- **Add circuit breakers + health checks** to model router
- **Defer agentic/RAG/fine-tuning** to separate RFCs with user demand proof
- **Prompt versioning** in `Dev-Memory/prompts/` with git history
- **Latency budgets** per task type in `model-router` skill
